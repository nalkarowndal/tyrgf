# Codex 마스터 프롬프트 — AURA Agent

## 0. 개발 임무

당신은 시니어 AI 에이전트 엔지니어, 풀스택 개발자, UI/UX 디자이너, 보안 엔지니어, QA 자동화 엔지니어로 구성된 개발팀의 역할을 수행합니다.

프로젝트명은 임시로 **AURA Agent**로 지정합니다.

최종 목표는 Hermes Agent와 OpenClaw의 우수한 설계 개념을 참고하여, 무료 AI API를 중심으로 동작하는 개인용 통합 AI 에이전트를 실제로 개발하는 것입니다.

이 프로그램은 ChatGPT처럼 쉽게 대화할 수 있어야 하며, 필요한 경우 AI가 계획을 세우고, 파일과 브라우저를 조작하고, 프로그램을 실행하며, 실행 결과를 확인하고 문제를 수정할 수 있어야 합니다.

단순 프로토타입이나 UI 목업으로 끝내지 마십시오. 실제로 작동하는 프로그램을 단계적으로 구현하십시오.

### 가장 중요한 프로젝트 원칙

**컴퓨터와 AI에 익숙하지 않은 사용자도 별도의 전문 지식 없이 설치하고 사용할 수 있어야 합니다.**

모든 화면은 명확한 목적을 가져야 합니다. 버튼, 설정, 권한, 오류 메시지에는 사용자가 이해할 수 있는 한국어 설명을 제공하십시오.

기능이 복잡하더라도 화면은 복잡하지 않아야 합니다.

사용자가 원하는 것은 AI의 기술적인 내부 구조를 직접 조작하는 일이 아니라, 자연어로 요청하고 결과를 확인하는 경험입니다.

## 3. 최우선 UI/UX 개발 지침

이 프로젝트에서는 사용하기 쉬운 인터페이스를 부가 기능이 아닌 필수 기능으로 취급합니다.

### 3.1 기본 디자인 방향

- 현대적이고 깔끔한 데스크톱 애플리케이션 스타일
- 지나치게 화려한 효과보다 가독성과 직관성 우선
- 일관된 아이콘, 여백, 타이포그래피와 색상 사용
- 기본 한국어 UI
- 라이트 모드 및 다크 모드 지원
- 데스크톱·태블릿·모바일 반응형
- 애니메이션은 상태 변화를 이해시키는 용도로 제한
- 불필요한 설정과 전문적인 옵션은 기본 화면에 노출하지 않음

### 3.2 화면 설계 원칙

모든 주요 기능에 아래 내용을 제공하십시오.

1. 기능 이름
2. 기능의 목적
3. 사용하면 어떤 일이 발생하는지
4. 사용자가 해야 할 행동
5. 실행에 필요한 권한
6. 예상되는 결과
7. 실패했을 때 해결 방법

도움말은 한 번에 장황하게 표시하지 마십시오.

기본 화면에는 짧고 쉬운 설명을 보여주고, 추가 설명이 필요한 경우 도움말 아이콘이나 펼치기 버튼으로 상세 내용을 표시하십시오.

### 3.3 초보자 모드

초보자 모드를 기본값으로 설정합니다.

- 전문 용어 대신 쉬운 한국어 표현 사용
- 중요한 기능 옆에 설명 표시
- 설정 과정은 단계별 마법사로 진행
- 사용하지 않는 고급 메뉴는 숨김
- 위험한 작업의 결과를 구체적으로 설명
- 오류가 발생하면 해결 방법 제시
- 처음 사용하는 기능은 짧은 사용 예시 제공

### 3.4 고급 사용자 모드

고급 사용자 모드에서는 다음 내용을 추가로 노출합니다.

- AI 모델 세부 설정
- 컨텍스트 및 토큰 예산
- MCP 서버 관리
- 도구 실행 정책
- 작업 추적 로그
- 개발자 콘솔
- API 요청 및 응답 정보
- 에이전트 실행 단계 세부 정보

초보자 모드와 고급 사용자 모드는 언제든 전환할 수 있어야 합니다.

### 3.5 UX 설명 시스템

재사용 가능한 다음 UI 컴포넌트를 설계하십시오.

- HelpTooltip
- FeatureExplanation
- PermissionExplanation
- GuidedStep
- ActionPreview
- ErrorRecoveryPanel
- EmptyStateGuide

- TechnicalDetailsDisclosure

기능 설명 예시:

기능명: 장기 기억

"저장된 기억은 언제든 확인하거나 수정하고 삭제할 수 있습니다."

UI에 기술 용어를 사용해야 한다면 반드시 쉬운 설명을 함께 제공하십시오.

## 4. 첫 실행 및 초기 설정 마법사

설치 직후 사용자가 무엇을 해야 할지 모르는 상황을 방지해야 합니다.

초기 설정은 다음 순서로 구성합니다.

### Step 1. 환영 화면

"안녕하세요! AI 도우미를 처음 설정해 볼까요?"

프로그램이 무엇을 할 수 있는지 세 가지 정도의 실제 예시로 소개합니다.

### Step 2. AI 연결

Gemini, Groq, Ollama 중 선택하도록 합니다.

각 서비스에 다음 설명을 제공합니다.

- 서비스의 특징
- 무료 사용 가능 여부
- API 키 발급 방법
- 이용 제한
- 데이터 처리 관련 주의사항
- 연결 상태

API 키 발급 페이지로 이동하는 기능과 연결 테스트 버튼을 제공하십시오.

### Step 3. 사용 권한

다음 항목을 개별 설정할 수 있도록 합니다.

- 웹 검색
- 브라우저 조작
- 선택한 폴더 읽기
- 선택한 폴더 수정
- 명령 실행
- GitHub 접근

기본값은 읽기 전용 또는 사용 안 함으로 설정합니다.

### Step 4. 첫 대화

사용자에게 다음과 같은 예시를 보여줍니다.

"안녕하세요. 어떤 일을 할 수 있나요?"

"이 일본어 문장을 자연스러운 한국어로 번역해 줘."

"선택한 폴더의 파일을 정리해 줘."

실제로 설정되지 않은 기능의 예시는 사용할 수 없음을 명확히 표시하고 설정 안내를 연결합니다.

### Step 5. 완료

연결된 모델, 허용된 도구, 저장소 상태를 요약합니다.

설정 완료 이후에도 각 항목을 쉽게 수정할 수 있어야 합니다.

## 6. AI 모델 및 무료 API 관리 시스템

### 6.1 다중 공급자 아키텍처

AI 제공자마다 API 형식이 다르므로 공통 Provider Adapter를 설계하십시오.

공통 기능:

- 모델 목록
- 메시지 전송
- 스트리밍
- 도구 호출
- 사용량 정보
- 오류 처리
- 기능 지원 여부 확인
- 호출 제한 정보
- 연결 상태 확인

모든 제공자가 같은 기능을 지원한다고 가정하지 마십시오.

### 6.2 무료 우선 정책

기본 모드는 Free-Only로 설정합니다.

- 유료 API 자동 사용 금지
- 유료 전용 기능을 무료 기능처럼 표시하지 않음
- 과금 가능성이 있는 설정은 기본 비활성화
- 사용자가 선택하지 않은 유료 모델로 자동 전환하지 않음
- 공급자별 무료 한도를 개별 관리
- 429 오류에 대한 재시도 정책 적용
- 사용자가 허용한 무료 대체 모델로만 전환
- 로컬 Ollama 모델 선택 지원

무료 한도는 고정 숫자를 무조건 표시하지 말고 실제 공급자의 문서, API 응답 또는 계정 설정을 기준으로 관리하십시오.

정확한 남은 사용량을 가져올 수 없다면 "예상 사용량"으로 명확하게 표기하십시오.

### 6.3 모델 선택 UX

각 모델 옆에 쉬운 설명을 표시하십시오.

예시:

Gemini Flash:
"긴 문서 분석과 복잡한 질문에 추천합니다."

Groq GPT-OSS:
"빠른 답변이 필요한 대화에 추천합니다."

로컬 모델:
"내 컴퓨터에서 실행합니다. 성능은 PC 사양에 따라 달라집니다."

### 6.4 대화 맥락 유지

- 토큰 사용량 관리

## 7. 에이전트 실행 엔진

### 7.1 에이전트 실행 흐름

다음 상태 기반 실행 구조를 설계하십시오.

사용자 요청
→ 요청 분석
→ 작업 계획
→ 필요 도구 선택
→ 권한 확인
→ 도구 실행
→ 실행 결과 관찰
→ 성공 여부 검증
→ 필요시 수정 및 재시도
→ 최종 보고

에이전트는 실행 결과를 관찰한 뒤 다음 행동을 결정해야 합니다.

성공 여부를 확인하지 않고 임의로 완료 처리해서는 안 됩니다.

### 7.2 Agent Runtime

필수 기능:

- 계획 수립
- 도구 선택
- 단계별 실행
- 작업 중단
- 작업 재개
- 실행 시간 제한
- 반복 횟수 제한
- 토큰 예산 제한
- 상태 저장
- 실패 원인 분석
- 재시도
- 최종 결과 검증

실행 상태를 SQLite 등에 영속적으로 기록하여 앱이 종료되어도 작업의 마지막 확인된 상태를 복구할 수 있도록 설계하십시오.

### 7.3 사용자 승인 시스템

에이전트가 실행하기 전에 사용자가 확인해야 할 작업을 분류하십시오.

특히 다음 작업에는 명시적인 승인이 필요합니다.

- 파일 수정 및 삭제
- 터미널 명령 실행
- 소프트웨어 설치
- GitHub 코드 푸시
- 외부 메시지 발송
- 외부 웹사이트에 정보 입력
- 개인 데이터 외부 전송
- 보안 설정 변경

승인 화면에는 다음 내용을 보여주십시오.

- AI가 하려는 일
- 작업 대상
- 예상 변경 내용
- 발생할 수 있는 위험
- 승인
- 거절
- 계획 수정

가능한 경우 실행 전 미리보기와 파일 변경 차이(Diff)를 제공하십시오.

## 14. Codex 실행 규칙

1. 기존 프로젝트가 있다면 먼저 분석하고 기존 코드를 무작정 제거하지 마십시오.

2. 새 프로젝트라면 모노레포 또는 이에 준하는 명확한 디렉터리 구조를 구성하십시오.

3. 문서만 생성하고 작업을 종료하지 말고 실제 코드 구현까지 진행하십시오.

4. 각 단계에서 코드 작성, 실행, 테스트, 오류 수정, 결과 검증 순서를 따르십시오.

5. 모든 UI 컴포넌트는 실제 기능 또는 명확한 비활성 상태와 연결되어 있어야 합니다.

6. 아직 구현되지 않은 기능은 "준비 중"이라고 표시하십시오.

7. API 키가 없는 상태에서도 개발 및 테스트가 가능하도록 모의 공급자를 구현하되 실제 공급자와 명확히 구별하십시오.

8. 외부 API 호출 실패 시 앱 전체가 종료되지 않도록 하십시오.

9. 각 단계가 완료되면 개발 내용, 테스트 결과, 남은 문제, 변경 파일, 다음 단계 계획을 기록하십시오.

10. 사용자의 추가 확인 없이 위험한 파일 삭제, 외부 정보 전송, 비용 발생 행위를 수행하지 마십시오.

11. 사용자 승인 단계에 도달하면 해당 작업을 일시 중단하고 승인 요청 상태를 보존하십시오.

12. 작업이 완료되지 않았는데 성공했다고 보고하지 마십시오.

13. 테스트를 실행할 수 없는 환경이라면 그 한계를 명시하고 실행하지 못한 테스트를 통과한 것으로 기록하지 마십시오.

14. 새로운 기능을 추가할 때 기존 기능에 대한 회귀 테스트를 실행하십시오.

15. 완성된 코드와 문서 사이에 불일치가 없도록 유지하십시오.
