# 영속 작업 에이전트 (M4)

`/tasks`의 AgentService는 LangGraph.js 1.5.0 StateGraph에서 계획 → 실행/승인 → 관찰 → 검증을 반복한다. 일반 대화는 도구를 호출하지 않는다. 실제 모델은 다음 동작 하나를 JSON으로 선택하며 서버의 엄격한 Zod 계약을 통과해야 한다. 지원 동작은 file.list, file.read, file.write, browser.read, finish다. 쉘·삭제·설치·메시지 발송은 계획자가 선택할 수 없다.

## 영속성과 재개
SQLite schema version 3의 agent_tasks에는 목표, 공급자/모델, 폴더 경로·inode 정체성, 상태·단계, 관찰, pendingAction, pendingRun, 예산을 보관한다. agent_checkpoints에는 라이브러리 MemorySaver의 storage/writes를 node:v8로 직렬화한 버전 1 스냅샷을 보관한다. 키는 어느 레코드에도 넣지 않는다.

그래프에는 taskId만 전달한다. 재개 호출은 저장된 작업 커서에서 다시 진입하며 tool_runs 영수증이 부작용 실행 여부의 기준이다. 네이티브 체크포인트는 그래프 진행을 보존하지만 오래된 노드의 부작용 재실행을 허용하지 않는다. 이 분리는 승인 영수증 저장 뒤 그래프 체크포인트 전에 서버가 종료되어도 파일 쓰기를 반복하지 않게 한다. MemorySaver 내부 형식과 V8 직렬화에 의존하므로 Node/LangGraph 업그레이드 전 기존 데이터 호환성 검사가 필요하다. 범용 분산 워커·체크포인트 이식성은 지원하지 않는다.

미리보기와 작업의 pendingRun은 같은 SQLite transaction에서 저장한다. 승인은 작업의 현재 상태와 정확한 run ID에 묶인다. 거절은 취소이며 자동 우회하지 않는다. 만료된 미리보기는 새로 만들고 다시 승인받는다. 서버 재시작 시 실행/승인대기/복구가능 작업은 paused로 바꾸며 폴더 권한과 키를 다시 받아야 한다. 처음 폴더의 경로·정체성과 공급자/모델이 같아야 재개한다.

## 검증과 오류
완료에는 성공한 도구 단계 2개 이상이 필요하다. 읽거나 저장한 각 파일의 마지막 fingerprint를 현재 파일과 비교한다. 변경·삭제·접근 불가이면 needs_review이며 성공 처리하지 않는다. 이는 파일 정체성·내용 검증이지 답변의 의미나 목표 달성의 완전한 증명이 아니다.

실행 중/중단/실패한 파일 쓰기의 결과는 불확실할 수 있으므로 자동 재시도·재계획을 금지하고 needs_review로 멈춘다. 이 상태는 pause/resume으로 우회할 수 없다. 도구 기록과 복구 위치를 직접 확인해야 한다. 실행 전 잘못된 모델 경로, 읽기 실패, 비변경 도구 실패는 관찰로 전달하고 남은 도구 예산 안에서 재계획한다. 계획·연결·권한 오류는 명시적 재개로 복구하며 누적 3번째 오류에서 failed가 된다. 오류 횟수는 pause나 재시작으로 초기화하지 않는다. 중단 뒤 늦게 도착한 모델 결과는 폐기한다.

작업당 도구 최대 8회(사용자 선택 2/4/6/8), 계획 호출 최대 12회, 활성 실행당 120초, 모델 입력 48,000글자, 계획 출력 28,000글자다. 한 번에 작업 하나만 활성 실행한다. 일시중지·승인 대기 시간은 활성 실행 시간에 포함하지 않는다.

## 공급자와 체험
실제 공급자에는 작업 전용 system 안내를 보내며 일반 대화의 도구 미지원 안내와 분리한다. 목표·관찰을 클라우드 모델에 보내려면 기존 계정 동의 외 작업별 전송 동의가 필요하다. 임의 공급자·유료 모델로 자동 전환하지 않는다.

모의 공급자는 사용자 목표를 추론하지 않는 고정 데모다. 폴더 목록 → 첫 txt/md 읽기 → aura-report.md 저장 승인 → 결과 검증을 수행한다. 파일 도구는 실제 실행되며 AI 요약이 아닌 원문 발췌임을 UI와 보고서에 표시한다. 실제 Gemini/Groq/Ollama의 자율 계획 품질은 키·실행 인스턴스가 없어 아직 검증하지 못했다.

독립 검토의 Important 3건(실패 쓰기 재실행, 복구 예산 우회, 대화용 system 충돌)을 수정하고 회귀 테스트로 검증했다. 남은 Minor: 하위 폴더 목록 조회의 원시 ToolService 영수증 도구명이 file.read로 표시될 수 있다. 작업 단계에는 file.list로 표시되며 권한·실행 동작에는 영향이 없다. 이 기록 명칭 정리는 후속 개선으로 남긴다.
