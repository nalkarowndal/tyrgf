# 보안 설계와 한계

## 현재 경계
단일 로컬 사용자용이다. Express는 127.0.0.1에만 바인딩하고 정확한 localhost/127.0.0.1 + port Host, 동일 출처 Origin, Sec-Fetch-Site를 검사한다. 쓰기 API에는 서버 재시작마다 바뀌는 랜덤 CSRF 토큰이 필요하다. CORS를 개방하지 않는다. 다른 로컬 프로세스·같은 OS 계정 사용자를 적대적 다중 사용자로 격리하는 인증 시스템은 아니다.

정적 배포에 CSP(default/script/connect self, object none, frame-ancestors none), nosniff, no-referrer, no-store, frame deny를 적용한다. Markdown raw HTML을 실행하지 않으며 외부 이미지를 로드하지 않는다. 외부 링크는 사용자가 클릭하고 새 탭 noreferrer로 연다.

## 비밀·저장소
API 키는 비밀번호 입력을 거쳐 같은 출처 서버 메모리 Map에 저장한다. 설정/SQLite/로그/오류/응답/export에 키를 포함하지 않는다. 재시작 시 재입력한다. 브라우저 입력 시점에는 키가 메모리에 존재하므로 악성 브라우저 확장까지 보호한다고 주장하지 않는다. OS vault는 M9 검토 대상이며 아직 구현하지 않았다.
데이터 디렉터리는 생성 시 0700, SQLite는 0600으로 설정한다. SQLite는 WAL, foreign_keys, secure_delete 사용. 디스크 암호화는 OS에 의존한다. 삭제는 논리 삭제이며 기존 백업·WAL·SSD 흔적의 포렌식 완전 삭제를 보장하지 않는다.

## 외부 호출
Gemini/Groq 고정 HTTPS 주소, Ollama loopback 11434만 사용한다. API 키·짧은 테스트 질문·선택 대화 내용의 전송은 사용자가 서비스 선택/동의 후 요청할 때만 수행한다. 기본 공급자는 오프라인 mock. provider redirect 금지, Ollama remote 모델 사전 차단. 네트워크 정책 자체를 OS 방화벽 수준으로 설정하는 기능은 없다.

## M3 도구 경계
파일 읽기는 허용한 폴더, 변경은 쓰기 권한과 서버 저장 미리보기의 1회 승인이 필요하다. Linux fd 기반 경로 고정, symlink/hardlink 거절, fingerprint 검사, 원본 격리 후 배타적 게시로 동시 파일 변경을 보존한다. 원본 복구 위치를 실행 전에 기록한다. 디렉터리 이동을 재검사하되 같은 OS 계정의 악성 동시 프로세스를 격리하는 OS 샌드박스는 아니다. 상세한 디렉터리 정체성 기반 권한과 복구 조건은 TOOL_MCP_DESIGN.md에 있다.

공개 웹 읽기는 DNS 주소를 검사해 연결 IP를 고정하며 리다이렉트를 거절한다. 원격 HTML 대신 추출·이스케이프한 본문만 오프라인 Chromium에서 렌더링한다. 웹 본문을 명령이나 승인으로 사용하지 않는다. 명령 실행, 브라우저 입력, 설치, GitHub push, 외부 메시지 발송, MCP 실행은 제공하지 않는다.

승인/로그/전후 내용/웹 결과와 원본 복구 파일에는 사용자 데이터가 포함된다. 암호화되지 않은 로컬 데이터이며 OS 계정과 디스크 암호화로 보호해야 한다. 앱 재시작 시 권한 해제, pending 만료, running 중단 처리하며 자동 실행하지 않는다.

## 복구와 한계
동일 대화의 생성 중 수정·삭제 금지. 응답 중단은 AbortSignal로 공급자 요청까지 전파. UI 중단은 이미 공급자가 소비한 사용량을 취소하지 않는다. 프롬프트 인젝션에 대한 system 안내는 보조 수단이며 강한 격리를 대체하지 않는다. 일반 대화에는 도구 호출을 연결하지 않았다. 작업 계획자는 엄격한 도구 계약과 서버 권한·승인을 통과해야 실행한다. 악성 문서가 답변 내용에 영향을 줄 가능성은 있다.

## M4 작업 경계
작업별 외부 AI 전송 동의가 있어야 목표·파일 관찰을 클라우드에 보낸다. 폴더 경로와 inode 정체성, 원래 공급자/모델을 고정한다. 모델 출력은 승인 상태나 권한을 지정할 수 없으며 실행 승인 요청은 서버 저장 run ID로 연결한다. 파일 쓰기 실패·중단은 이미 변경된 결과일 수 있으므로 자동 재실행하지 않는다. 결과가 확인되지 않는 상태는 재개를 금지한다. 늦게 도착한 모델 결과는 중단 신호 검사로 폐기한다.

작업 목표·관찰·결과·체크포인트는 로컬 SQLite에 보존한다. 관찰에는 파일 본문이 포함될 수 있다. API 키는 저장하지 않는다. 현재 작업 기록 개별 삭제/내보내기 UI는 없으며 장기 보존 관리가 후속 작업이다. 관찰에 포함된 악성 텍스트가 모델 선택에 영향을 줄 수 있으므로 쓰기/웹 전송의 실제 대상과 내용을 사용자가 확인해야 한다. 계약 검증만으로 프롬프트 인젝션을 완전히 방지한다고 주장하지 않는다.

## M5 기억·스킬 경계
기억은 명시적 버전 승인 후 대화에 포함하며 저장된 원문 메시지에 주입 내용을 복사하지 않는다. 수정·삭제 시 모델 요청 중단과 대화 범위 경계 갱신으로 이전 응답을 통한 재유입을 막는다. 이미 전송한 데이터 회수는 지원하지 않는다. 요약은 원문 해시·기억 epoch·공급자 설정을 확인하고 늦거나 오래된 응답은 저장하지 않는다. 원문을 사람이 수정한 기억은 사용자 작성으로 구분한다.

스킬은 완료 작업의 절차만 초안으로 저장하고 필요한 권한을 서버에서 파생한다. 매 실행 전에 승인된 정확한 버전을 확인하며 도구 allowlist를 강제한다. 기억과 절차는 시스템 권한을 부여하지 않는다. 기억/요약/스킬과 export에는 개인정보가 포함될 수 있으며 OS 계정·디스크 암호화에 의존한다. 외부 설치·자동 민감정보 추출·모델의 승인 API 호출은 제공하지 않는다.
