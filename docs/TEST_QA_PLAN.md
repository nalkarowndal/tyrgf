## E2E 시나리오
1. 첫 실행 5단계 → 명시된 모의 연결 테스트 → 채팅 → 새로고침 후 기록 → 제목 변경 → 재생성 → 테마 저장 → 연결 설정 저장 뒤 테마 보존 → 모바일 메뉴.
2. 대화 A 편집 중 B 이동 → 초안/편집 상태 분리. A 응답 지연 중 B 이동 → A 내용이 B 화면에 나타나지 않음.
3. 동의 없는 Groq 연결 오류 → 모의 공급자로 복구 → 텍스트 첨부 → 질문 편집 → 본문 검색 → 삭제 확인.

첫 구현 전에 테스트 실패를 확인했다. 이후 Zod partial 기본값 덮어쓰기, 별도 폼의 오래된 설정 저장, mixed-case 토큰 우회는 회귀 테스트 실패 후 수정했다. 대화 상태 문제는 독립 브라우저 재현과 라우트 전환 E2E로 검증했다. fixture 초기화는 응답 헤더뿐 아니라 스트림 본문 종료까지 기다려야 함을 수정했다.

## 미검증·후속 조건
Groq 키는 제공되었지만 개발 환경 네트워크 허용 목록에 api.groq.com이 없어 키를 전송하지 않았다. Gemini/Groq 인증 응답·계정 요금제·실 사용 한도는 미검증. Ollama 실 인스턴스 없음: 설치 모델 실제 추론 미검증. fetch fixture를 실 API 연결 증거로 취급하지 않는다. M3 수동 도구 승인·실행·복구는 검증했다. 공개 사이트 라이브 읽기는 환경 DNS EAI_AGAIN으로 실패하여 성공 미검증이다. M4 복합 파일 도구 실행은 명시적 모의 계획으로 검증했으며 실제 모델 계획 품질은 미검증이다. M5 기억 삭제와 파생 컨텍스트 제외, 스킬 재사용은 검증했다. M6 내장 MCP 실제 stdio 연결·호출과 프로토콜 fixture를 검증했다. GitHub/Serena/Repomix 외부 설치·인증 연결은 미검증이며 REA는 안내만 제공한다. Windows 런타임·Edge 자동 검수는 후속 단계에서 통과했다. Windows 설치 GUI·macOS·추가 브라우저·실제 초보자 사용성 실험·OS credential vault는 후속 검증이다.

빌드 경고: 현재 단일 프론트엔드 bundle이 약 655KB(압축 약 200KB)로 Vite 권고 기준을 넘는다. Zod 내부 PURE annotation 경고도 발생하지만 빌드 실패는 아니다. 코드 분할은 후속 성능 개선 항목이다.

- 브라우저 실제 시나리오: 폴더 선택 → MCP 등록 → 실행 확인 → 연결/도구 발견 → 읽기 권한 저장 → JSON 입력 승인 → 실제 파일 결과 → 모바일 해제. 390px 가로 넘침 없음. desktop-mcp.png/mobile-mcp.png를 직접 확인했다.
- 외부 서버 설치·실 GitHub PAT 인증·Serena 언어 서버·Repomix 실제 배포 버전은 검증하지 않았다. 테스트 fixture와 실제 외부 서비스 성공을 구분한다.
- 기존 Zod 주석 제거 및 500KB 초과 번들 경고가 남아 있다. 운영 의존성 audit 취약점 0건.

- 독립 검토 Important 1건: 앱의 100ms 강제 종료가 MCP 자식 종료보다 먼저 실행되던 문제를 회귀 테스트 RED→GREEN으로 수정했다. 실제 앱 프로세스와 stdin EOF/SIGTERM을 무시하는 자식으로, 해제 중인 연결까지 종료/수거한 뒤 부모가 끝나는 것을 확인했다.
