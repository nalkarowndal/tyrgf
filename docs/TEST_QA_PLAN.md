# 테스트 및 시각 QA

## 실행 결과 (2026-10-16)
검증 환경: Linux, Node 24.19.0, 시스템 Chromium. `npm run check` (타입 검사, ESLint, Vitest, Vite 빌드) 통과. Vitest 13개 파일 **83개 테스트 통과**. `npm run test:e2e` **7개 사용자 시나리오 통과**. 운영 의존성 `npm audit --omit=dev` 알려진 취약점 **0건**. Windows CI workflow는 작성했지만 원격 실행하지 않았다.

## 기능·보안 검사
- API 기본값 mock/외부 전송 차단, Host/Origin/토큰 검사, 대소문자 경로 우회 차단.
- 설정 검증, 키 DB/응답/export 비노출, 유료 모델·임의 Ollama 출처 거절.
- 대화 스트리밍/재시작 영속성, 생성·검색·제목 변경·편집·재생성·삭제·내보내기.
- 진행 중 중단→부분 응답 보존, 동일 대화 동시 변경 409, 재시작 interrupted 복구.
- 분할 UTF-8 SSE, CRLF, 마지막 줄 개행 없는 NDJSON, 잘못된 이벤트, 불완전 스트림.
- Gemini systemInstruction/생성 프로토콜/사고 텍스트 제외, Groq delta/usage, Ollama show/chat 및 remote 모델 차단.
- 429 단기 제한 1회 재시도, 긴 제한 즉시 안내, 취소 전파.
- React Testing Library: 클라우드 동의 기본 비선택, 키 password 입력, 실패 시 복구 안내 및 성공 표시 금지.

## E2E 시나리오
1. 첫 실행 5단계 → 명시된 모의 연결 테스트 → 채팅 → 새로고침 후 기록 → 제목 변경 → 재생성 → 테마 저장 → 연결 설정 저장 뒤 테마 보존 → 모바일 메뉴.
2. 대화 A 편집 중 B 이동 → 초안/편집 상태 분리. A 응답 지연 중 B 이동 → A 내용이 B 화면에 나타나지 않음.
3. 동의 없는 Groq 연결 오류 → 모의 공급자로 복구 → 텍스트 첨부 → 질문 편집 → 본문 검색 → 삭제 확인.

첫 구현 전에 테스트 실패를 확인했다. 이후 Zod partial 기본값 덮어쓰기, 별도 폼의 오래된 설정 저장, mixed-case 토큰 우회는 회귀 테스트 실패 후 수정했다. 대화 상태 문제는 독립 브라우저 재현과 라우트 전환 E2E로 검증했다. fixture 초기화는 응답 헤더뿐 아니라 스트림 본문 종료까지 기다려야 함을 수정했다.

## 미검증·후속 조건
Groq 키는 제공되었지만 개발 환경 네트워크 허용 목록에 api.groq.com이 없어 키를 전송하지 않았다. Gemini/Groq 인증 응답·계정 요금제·실 사용 한도는 미검증. Ollama 실 인스턴스 없음: 설치 모델 실제 추론 미검증. fetch fixture를 실 API 연결 증거로 취급하지 않는다. M3 수동 도구 승인·실행·복구는 검증했다. 공개 사이트 라이브 읽기는 환경 DNS EAI_AGAIN으로 실패하여 성공 미검증이다. M4 복합 파일 도구 실행은 명시적 모의 계획으로 검증했으며 실제 모델 계획 품질은 미검증이다. M5 기억 삭제와 파생 컨텍스트 제외, 스킬 재사용은 검증했다. M6 MCP 설치는 구현 전이므로 테스트 통과로 기록하지 않는다. Windows/macOS·다중 브라우저·실제 초보자 사용성 실험·OS credential vault는 후속 검증이다.

빌드 경고: 현재 단일 프론트엔드 bundle이 약 628KB(압축 약 192KB)로 Vite 권고 기준을 넘는다. Zod 내부 PURE annotation 경고도 발생하지만 빌드 실패는 아니다. 코드 분할은 후속 성능 개선 항목이다.

## M3 추가 검증
- 파일 API: 권한 기본 꺼짐, CSRF, 읽기/쓰기 분리, 승인 전 무변경, 승인 입력 위변조·재실행 거절, 경로 우회/숨김/심볼릭·하드링크/비텍스트 거절, 외부 수정 보존, 루트 교체, 권한 철회, 삭제·복구·변경 후 복구 거절, 만료와 재시작.
- 독립 리뷰 재현: 최종 확인 후 외부 수정 및 하위 디렉터리 이동을 테스트에서 syscall 사이에 삽입. RED 확인 후 원본 격리·배타적 게시·위치 재검사로 GREEN. 원본 복구 경로의 실제 내용도 확인.
- 웹 경계: 사설/예약/인코딩 IP·인증정보·포트 차단, 공용/사설 혼합 DNS 차단, 검증 주소로 lookup 고정 및 TLS hostname 유지, 리다이렉트 거절. 이 네트워크 경계 검사는 통제된 resolver/HTTP fixture를 사용한다.
- 실제 Chromium: HTML fixture의 script/meta refresh/외부 image/iframe을 실행하지 않고 추출 텍스트와 PNG 생성. 제품 URL 요청의 실 인터넷 성공 검증과는 다르다.
- 도구 서버: 승인 전 호출 없음, URL 불변, 중복 실행 거절, 실행 중 권한 해제→취소, 대기 요청 무효화, 상태 polling의 스크린샷 제외와 상세 조회.
- E2E 4: 폴더 허용→파일 생성 승인→읽기→삭제 승인→복구 승인→외부 편집 충돌→권한 철회, 모바일 가로 overflow 검사.
- E2E 5: 웹 권한→내부 주소 거절→공개 URL 미리보기→명시적 거절→권한 해제. 외부 네트워크 요청은 하지 않는다.
- qa/desktop-file-approval.png, qa/mobile-files.png를 직접 열어 확인. qa/desktop-browser-tools.png도 기록.
- CI에서 Chromium 설치를 check 앞으로 옮겼다. Linux 전용 파일 테스트는 다른 OS에서 건너뛰고 기본 권한 API는 계속 검사한다. Windows 원격 실행은 아직 하지 않았다.

## M4 추가 검증
- 작업 API: 최소 2개 도구 복합 작업, 현재 run ID 승인, 성공 결과 fingerprint, 외부 결과 변경·원본 삭제 시 완료 금지, 승인 거절의 최종성, 도구 예산, 작업별 클라우드 동의, CSRF.
- SQLite 재시작: 승인 영수증 저장 후 재개 시 쓰기 중복 없음, 대기 미리보기 만료 후 새 승인, 원래 폴더/모델 외 재개 거부. 체크포인트 저장 확인.
- 계획·제어: 지원하지 않는 도구/승인 필드/JSON 거절, 실제 공급자 스트림의 계획 해석과 사용량, 일시중지 후 늦은 응답 폐기, 너무 이른 완료의 재계획, 차단된 상대 경로를 실패 관찰로 전달.
- 리뷰 회귀: 실패 쓰기 영수증은 자동 재계획 금지, pause로 복구 예산 초기화 불가, 결과 확인 상태의 pause/resume 금지. streamReply를 대체하지 않고 fetch fixture로 공급자에게 보내는 실제 system 정책과 대화용 정책 분리를 검사한다.
- E2E 6: 폴더 권한 → 고정 모의 복합 작업 → 저장 미리보기 → 일시중지 → 새로고침·재개 → 명시적 승인 → 실제 보고서 내용·검증 결과 → 새로고침 영속성 → 모바일 가로 overflow 확인.
- qa/desktop-agent-approval.png: 전체 승인 카드. qa/mobile-agent-result.png: 모바일 검증 결과.
- 남은 Minor는 AGENT_DESIGN.md의 원시 하위 폴더 목록 영수증 명칭 문제. 테스트 통과가 실제 AI 추론이나 답변의 의미적 정확성을 증명하지는 않는다.

## M5 추가 검증
- 기억 API: 초안은 미적용, 정확한 버전 승인, 편집 시 승인 해제, 검색·분류·내보내기·개별/전체 삭제·재시작 영속성·CSRF·현재 문맥 길이 제한.
- 실제 Provider 스트림 경로를 사용한 fetch fixture: 새 대화의 전송 본문에 승인 기억 포함, 삭제 후 동일 대화에서 이전 파생 응답까지 제외. 원문 메시지에 주입 내용을 저장하지 않는지 확인. 실제 Groq 호출은 아니다.
- 요약: 모의 발췌 표시와 출처, 원문 변경 시 재승인/컨텍스트 차단, 공급자 실패 시 원문 보존, 삭제와 겹친 늦은 결과 저장 금지. 사람이 고친 요약은 사용자 기억으로 검토 가능.
- 스킬: 완료 전 작업에서 저장 거절, 초안 실행 금지, 정확한 버전 승인, 새 작업의 새 파일 승인, 스킬 삭제 후 대기 작업 승인 거절, 편집 후 승인 해제와 도구 allowlist 강제, 마지막 실행 결과.
- E2E 7: 기억 작성·승인·검색·수정·내보내기, 이전 컨텍스트 제외 후 요약 거절 안내, 새 대화의 모의 요약 초안, 전체 삭제 확인, 모바일 폭. 작업 E2E도 완료 절차 저장·스킬 승인·재사용·파일 실행 거절까지 확장.
- 첫 브라우저 검증 6/7: 기억 수정 후 이전 원문을 요약하려는 fixture가 유효 범위 제외로 실패. 차단 안내와 새 원문 준비를 시나리오에 명시해 수정 후 7/7 통과.
- qa/desktop-memory.png, qa/mobile-skills.png를 직접 열어 승인 상태·본문·권한·버튼과 모바일 줄바꿈 확인.

- M5 독립 검토 회귀 4개 RED→GREEN: 스킬 삭제/편집 뒤 일반 도구 승인 경로에서도 파일 변경 차단; 요약된 원문 질문 편집/답변 재생성 요청 본문에서 무효화 예정 요약 제외. 전체 83개 통과. 독립 검토의 실 Groq 품질 판단은 환경 제한으로 미검증이며 E2E·화면은 별도 실제 실행으로 확인했다.
